# Project Planning

## 目的

把模糊需求通过**对话协作**转化为可审查、可最终校验、可一次最终确认后写入 Linear 的项目方案。规划不是一次性产出 write plan，而是先收敛理解，再出计划。

## 五步协作循环

按顺序执行；任一步信息不足时暂停追问，不得跳过直接写 Milestones/Issues。

**硬顺序**：步骤 1 → 2 → 3 → 4 完成后，才允许 (a) 请用户选择/拍板方案，(b) 输出 `## 收敛计划`。**禁止**在 `### 方案对比` 后直接询问「你选哪个方案？」而未输出 `### 假设挑战` 与 `### 事实锚定`。用户无需提醒「先别收敛」——Agent 须主动继续步骤 3–4。

若单轮篇幅不足，在同一 `## 协作对话` 段内按序分节输出；可在段末预告下一步，但不得跳过或等待用户催促。

### 1. 逼问四格（What / Why / Who / How）

对每个核心需求块，至少覆盖四格；缺失格必须列出待确认项，不得用假设填充：

| 格 | 追问方向 |
|---|---|
| **What** | 具体交付物是什么？边界在哪？ |
| **Why** | 解决什么问题？不做会怎样？ |
| **Who** | 谁用、谁维护、谁验收？ |
| **How** | 技术路径、依赖、约束、非目标？ |

输出：`## 四格澄清` 表格或列表，标注已确认 / 待确认。

### 2. 给出 2–3 个带权衡的方案

至少 2 个可行方案，每个方案必须显式列出：

- 优点与适用场景
- 代价、风险、工期或复杂度
- 对架构 / 数据 / 运维的影响
- 推荐与否及理由（可标注「推荐」但不得只给一个方案）

输出：`## 方案对比` 表或分节描述。

### 3. 挑战假设（≥ 1 个）

从 Fact Pack、用户陈述或方案推导中，**主动挑战至少 1 个关键假设**。格式：

- 假设内容
- 若假设不成立的影响
- 验证方式或需要用户确认的问题

不得跳过此步；无假设可挑战时，应说明「当前无未验证假设」并引用已锚定事实。

输出：`## 假设挑战` 列表。

### 4. 锚定事实

引用 Fact Pack（或当场采集的 compact 摘要 + `evidenceRef`），区分：

- **已证实事实**（有来源）
- **仍属假设**（待用户或 readback 确认）
- **证据缺口**（影响规划决策的缺失项）

不得将 GitHub/Linear/本地 repo 未读取的内容写成事实。证据不足时，标记 `evidence_gap` 并暂停写入计划。

输出：`## 事实锚定`（事实 / 假设 / 证据缺口）。

### 5. 收敛后出计划

仅在四格基本闭合、方案已选或待用户拍板、假设已挑战、事实已锚定后，输出完整项目计划：

- 目标用户、场景、问题、目标、**非目标**
- MVP / vNext / Later
- 成功指标与验收口径
- Milestones、Issues、Relations（Issue 须独立可执行、带验收标准与 labels）
- 风险、依赖、待确认项
- write plan 摘要（随后必须经 `linear_validate_write_plan` 一次最终校验）

输出：见 `00-linear-admin-core` **收敛计划** 段格式。

## 收敛计划事实一致性

`## 收敛计划` → `### 事实` **仅**可包含：

- `### 事实锚定` 中 **已证实事实** 已列出的项；或
- 用户在当前对话中 **明确口头确认** 的内容。

**禁止**同一条目同时出现在 `### 事实` 与 `### 假设` / `### 待确认项`（例如：Task Scheduler 未验证时不得写入事实，只能留在假设或待确认项并注明验证方式）。

## 质量门禁

以下任一情况**不得**进入 write plan / final validation：

- 四格有关键格仍为「待确认」且影响范围或架构选型
- 方案少于 2 个且无用户明确指定唯一路径
- 未挑战任何假设且无「无未验证假设」说明
- 事实锚定缺失（无 Fact Pack 且无 evidenceRef）
- 非目标或成功指标缺失
- `orchestration-policy.yaml` 中 `planning.dialogue` 软门禁未满足

## 与写入协议的关系

本 skill 只负责**规划对话与计划草案**；真实 Linear 写入仍须：`linear_validate_write_plan` 一次最终校验 → 一次 `plan_confirmation` → apply → readback → audit。本 skill 不替代 write guard。
